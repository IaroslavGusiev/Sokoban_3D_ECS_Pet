# ECS component audit

Checked against project-owned source on 2026-10-27. Scope: Core and presentation ECS data, tags, requests, query membership, nested movement records, and the presentation ownership reference stored on entities. Vendored code, unrelated DTOs/configuration, and new gameplay contracts are excluded. This is an inventory and a set of proposals, not authorization to implement the proposals.

Only the ActorViewState split is implemented here. Core, recording/replay, snapshots, assemblies, packages, serialized assets, and factory/composite ownership are unchanged. The starting working tree and index were clean at `5090521a33869f2ded2df3c8806b0025ac66c60b`.

## Reading the inventory

Writer includes creation, replacement, and removal; reader includes query-only use. Production uses are listed rather than repeating test fixtures. `entity.Set`/`Remove` are the value-component change boundary. Managed objects and Unity objects also have deliberately mutable internals; an immutable wrapper or readonly reference would not freeze them.

Recommendation scope is **presentation-only**, **Core-propose** (requires later approval), or **excluded** (retain; no change proposed here). Risk is the risk of the suggested change, or the invariant that makes retention safe. Source paths are relative to this document. Short system names refer to [Core systems](../Sokoban/Assets/_Sokoban/Code/Core/Ecs/Systems) or [presentation systems](../Sokoban/Assets/_Sokoban/Code/Unity/Ecs/Systems).

## Equality, collections and excluded adjacent types

- GridPosition equality/hash use exact integer coordinates; movement maps depend on Set notifications and support one box/wall per coordinate in the supported board. Hash collisions are handled by equality. Do not use a Unity float position or presentation snapshot as an occupancy key.
- [ViewKey](../Sokoban/Assets/_Sokoban/Code/Unity/StaticData/ViewKey.cs) is presentation cache metadata, not an ECS component: Kind and Skin form exact value equality/hash. ViewAssets resolves skin fallback before selecting the cache key. Keep both; string formatting is not identity. ViewKind/SkinId are serialized catalog enums and must preserve numeric values.
- Binder and feedback dictionaries use full DefaultEcs Entity equality, including world/slot/generation. ViewOwnership and ViewLoadOperation additionally use reference identity for ownership and request validation. Neither reusable numeric IDs nor position equality can replace those checks. Ownership records are removed on the next presentation tick; an enabled-system check cannot be deleted just because values became readonly.
- [BoxEnteredGoal](../Sokoban/Assets/_Sokoban/Code/Core/Messages/BoxEnteredGoal.cs) is a readonly message (Entity Box, GridPosition Goal), not an installed component. GoalTrackingSystem publishes it; presentation buffers then validates it on its own tick. Keep event payload separate from active feedback state and observed positions. No Unity serialization. **Excluded** from change.
- HintSolver.State is a private per-call search key, not ECS data. Canonically ordered box arrays plus player position determine equality/hash; FirstMove is path metadata. Arrays are mutable despite get-only references, but the current solver clones before a push and shares arrays only for unchanged states. Do not expose/mutate a key after insertion into HashSet. No search changes proposed or implemented here.
- ViewContext, ViewLoadOperation, completion records, cached Addressables handles, run options, hint operations, recording/snapshot DTOs, and serialized configuration are not ECS components. They remain with their existing owners. No ECS entity or component should own/release shared prefab handles. Cancellation of one waiter does not release ViewAssets' shared operation. **Excluded** from this implementation.

Existing small pure helpers already isolate ViewMove advancement/interpolation, grid-to-world projection, and movement destination calculation. Retain them. The solver step helper enforces authored board dimensions, while runtime movement planning enforces Int32 overflow limits; unifying those helpers would risk changing their different contracts. No additional helper type or general arithmetic cleanup is justified by this component split.

## Implemented split and validation

ObservedPosition and ActorFacing are constructor-initialized readonly values with get-only Value properties. ActorQuery and buffered child iteration are retained. Initialization adds only ObservedPosition; detection compares its value to GridPosition. Push classification still runs in PreUpdate before any observed-position writes, with both deltas calculated using long. Detection retargets from current ViewMove.Position, adds/replaces facing only for a moved player, and replaces ObservedPosition through Set. Advance remains third and advances new steps in the same update.

Binding and projection use ActorFacing presence, still gated by PlayerTag. Without it they preserve authored prefab rotation; with it they preserve existing player facing. Skin replacement removes only instance/adapter state, keeping observation, facing and ongoing interpolation. No cancellation, generation/liveness, request identity, disposal, partial-construction or enable guard was removed. Only the obsolete HasFacing boolean predicate was replaced by component presence.

Fresh baseline: EditMode 294/294; PlayMode 194/195 with a Unity Package Manager HTTP 400 access-token error logged during AddressAndLabelLoads_UseBuiltContentAndRetainIndependentOwnership. That test passed unchanged on a focused 1/1 rerun. Full reports and subsequent checks are retained under ignored `Sokoban/Logs/component-audit/`. Final checks passed 29/29 focused motion/projection, 14/14 normal ViewLayer flow, 296/296 project EditMode, and 197/197 project PlayMode. Every baseline test FullName remains and passes; two new cases were added to each suite. Existing push-order/overflow, same-update advancement, retargeting, undo, animation, hints, dynamic cleanup and saved-scene cases remain passing. New cases cover late box initialization/no box facing, Set notifications and immutable snapshots, authored player/box rotations, no floor motion state, and immediate/delayed skin replacement during interpolation. The saved GameplayScene is clean and the Editor is stopped. No assets/content changed; existing packed Addressables content was reused without rebuilding. No standalone player build or vendored dependency suite was run. No new internals or assembly friendships were exposed. Changes remain uncommitted and staging unchanged.
